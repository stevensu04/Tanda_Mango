# FRAME / ESCAPE｜Hackathon 遊戲企劃書

> 題目：Brought to Life｜版本：v2（2026-11-20 晚）｜數值都是起始值，要用試玩再調整。
>
> 相對初版的主要改動：分房、每廳搶前三名、警衛改成電量制、照射整段地面、被抓定身 1 秒、判定寬限 0.15 秒、一局改成 45 秒、三條平行走廊改成一廳一條、每廳一個 bot 警衛加上真人警衛巡邏。

## 一句話

你是美術館裡一幅活過來的畫。45 秒內從畫框溜出去、躲過警衛的探照燈，在關門前搶先逃出去。全場約兩百人各自用手機同時玩，分成十個展廳，每廳搶前三名；前三名的肖像最後會掛上大螢幕的名人堂。

一句話講給觀眾聽：美術館版的「一二三木頭人」。大家都玩過，不用教規則。

## 1. 比賽條件（主辦投影片）

- **Brought to Life 的判準**：評審用自己手機打開的連結、群眾能一起玩的多人遊戲／工具／玩具、端到端真的會動。投影片、截圖、錄影、存到不知道哪裡的表單、只有自己隊伍跑得起來的東西都不算。
- **評分**：創意與想像、完成度與細節、互動性、技術巧思（聰明地解決難題，而不是為了複雜而複雜）、現場呈現（讓全場嗨起來）。
- **流程**：每隊 2 張投影片，約 2 分鐘 pitch、2 分鐘讓全場玩；評審會親自試過每個專案。
- **截止**：投影片寫週六 [4:30pm] 前把連結貼到 #showcase（括號看起來像待定）。**待確認**：截止時間，以及截止後能不能繼續更新同一個網址。
- **網路**：禮堂有自己的 Wi-Fi，全場都會連它，主辦要求 demo 前先測。

## 2. 設計目標

1. **加入就是第一個好玩的時刻**：掃碼、點一下座位區，你的肖像就眨眼、從畫框裡走出來。不用打名字、不跳授權、不聽規則。
2. **規則一句話**：按住就跑，放開就停；停在畫框裡就是一幅畫；黃燈亮了快躲。
3. **逃出去不難，搶前三才難**：難度來自玩家自己的貪心，而不是燈。
4. **真人警衛帶來真正的不確定**：連我們都猜不到這一場會怎麼打。
5. **抬頭的理由**：展廳對應座位區，對手就坐在你旁邊；真人警衛走進哪一廳，那一區就會哀嚎。

## 3. 規模與分房

- 預估約 200 人。每個展廳 15–25 人（目標 20），大約 10 廳。
- **分房**：加入時點一下「你坐哪一區」（禮堂座位分區圖），同一區就是同一個展廳；一區超過 25 人就自動拆成 A、B 廳。展廳用美術館的名字（例如文藝復興廳、印象派廳、現代館）。
- **一廳一條走廊**：原本三條平行走廊的設計取消，用分房取代。
- **bot 補位**：任何展廳少於 12 人就用 bot 補，畫成半透明的「幽靈訪客」。評審之後一個人打開時也有對手。
- **開局後才進來的人**：直接從出生框加入，可以拿名次，但不算進警衛要擋的人數。

## 4. 畫面

### 4.1 玩家手機

- **上方**：展廳名、目前名次（例如「第 4 / 20 名」）、倒數。
- **中間**：你這一廳的走廊縮圖。畫框、安全區、黃燈／白光、出口、其他玩家的小點；你自己放大並加框。旁邊顯示警衛電量。
- **下方**：兩個大按鈕，◀ 後退、▶ 前進。按住移動，放開就停。
- **回饋**：
  - 變成肖像：框亮起。
  - 被抓：全螢幕閃紅（旁邊的人看得到），顯示「被抓到了・還能再跑」。
  - 逃脫：金色畫面「逃脫成功・第 X 名」。
  - 時間到還在館內：「出口已關・未逃脫」。
  - 真人警衛進入你的展廳：「⚠️ 真人警衛進來了」。

### 4.2 警衛控制畫面（手機版）

- 目前展廳的走廊與所有玩家的位置、電量、切換展廳的按鈕。
- 點一段走廊就鎖定位置：先亮黃燈，再閃白光。
- （選做）取消黃燈＝假警報。

### 4.3 投影（共用監控畫面）

- **主畫面**：真人警衛所在的展廳，放大顯示。
- **旁邊**：其他展廳的小窗（一條線加小點）。
- 各廳即時前三名、全場倒數、總逃脫人數。
- 平常只畫點，有人被抓或逃脫時才跳出代號。
- **結束時**：名人堂，各廳前三名的肖像一幅一幅掛上牆。

### 4.4 角色與動畫

- 代號是「顏色＋動物」（例如藍狐），全場不重複；肖像是同色的動物畫像，裝在金框裡。
- 跑步：一個圓頭、一個身體、兩條腿。移動時兩腿反向擺動、身體輕微上下起伏，約 0.35 秒一輪；停步就停止擺腿。
- 在框內停下就切成同色肖像；被抓時短暫閃紅，再回到安全框。

## 5. 玩家規則

- 按住前進或後退，放開就停。
- 停在畫框的安全區內（地面標記），角色立刻變成肖像、框亮起；判定看角色腳下的中心點。只是跑過安全區，仍算人形。
- 成功變成肖像時，更新自己的退回點；出生框就是第一個退回點。同一個畫框可以容納多人。
- 看到黃燈時：還沒進去就等；剛跑進去就退；快到另一端就往前衝；已經是肖像的，可以等白光閃完再走。
- 跨過出口線立刻逃脫，依時間排名。
- 被白光抓到：退回上一次藏身的框，定身 1 秒（閃紅），之後可以繼續跑。
- **勝負**：每廳最快逃出的前三名是贏家；其他逃出去的人是「逃脫成功」；45 秒到還在館內就是「未逃脫」。就算警衛守住了展廳，逃出去的人仍然算贏。

## 6. 警衛規則

- 每次選一段走廊的地面（兩個畫框之間，不含安全區），照射範圍是整段地面。
- 先亮黃燈 1 秒，接著閃白光，只判一次：角色中心在照射區內、而且仍是人形，就被抓。其他路段、肖像、已逃脫的玩家都安全。
- **電量制**：最多存 2 格，每 2.5 秒回 1 格，每開一次燈用掉 1 格；同一時間只會有一道燈。玩家手機看得到電量，「警衛沒電了，衝！」就是一個要判斷的時機。
- （選做）**假警報**：取消黃燈，電量照扣。
- **警衛勝負**：開局時鎖定每廳人數，時間到時擋下過半（20 人的展廳要留下 11 人）就算守住該廳。
- **bot 警衛**：每廳一個。瞄準「一秒後最多人卡在長段中間」的那一段，兩成機率隨機選，強度比真人稍弱。
- **真人警衛巡邏**：請一位評審擔任，一次接管一個展廳，可以自己切換（或每 15 秒自動換廳）。第一站去評審們坐的那一廳。

## 7. 數值（起始值）

長度用「跑步秒數」表示：角色每秒前進 1。

| 項目 | 初版 | 目前（v2） |
|---|---|---|
| 一局時間 | 60 秒 | 45 秒 |
| 走廊 | 短段 1 秒、長段 2 秒 | 8 段：1、2.5、1、2、1、2.5、1.5、2.5（不停跑完 14 秒，最後一段是長段） |
| 安全區 | 未定 | 畫框前後各 0.25 |
| 照射寬度 | 半個框距 | 整段地面 |
| 黃燈 | 1 秒 | 1 秒 |
| 警衛節奏 | 固定冷卻 3 秒 | 電量 2 格，每 2.5 秒回 1 格 |
| 被抓 | 退回上一個框 | 退回上一個框，再定身 1 秒 |
| 判定寬限 | 無 | 0.15 秒（畫面在 1.0 秒閃白，伺服器在 1.15 秒判定） |
| 勝負 | 逃出去就贏 | 每廳前三名 |
| 每廳人數 | 未定 | 20（15–25），bot 補到至少 12 |

## 8. 為什麼這樣改

初版有一個零風險的打法：**躲在框裡，等白光閃完再跑。**

- 白光之後至少 4 秒不會再閃（冷卻 3 秒＋黃燈 1 秒）。一段只要跑 1–2 秒，閃完再跑一定來得及。
- 照射區只有半個框距，站在裡面任何位置，離邊緣最多 0.5 秒，1 秒的黃燈一定躲得掉；只有分心或網路延遲的人會被抓。
- 被抓只損失 1–2 秒，60 秒又遠比跑完走廊需要的時間長，所以幾乎人人都逃得出去。

改版後：

- 搶前三名讓「等安全時機」變成會輸的打法，想贏就得冒險。
- 電量制讓警衛可以連發，沒有固定的安全期。
- 照射整段地面後，站在長段中間被照到就躲不掉，「過長段」變成真正的賭注；短段仍然躲得掉。
- 定身 1 秒讓被抓等於掉好幾名。
- 判定寬限把網路延遲造成的冤枉拿掉。

## 9. 公平性與延遲

- **輸入**：送「按下／放開」事件，按住期間每 200ms 補一次保活；伺服器 500ms 沒收到就讓角色停下，避免「放開」的封包晚到，角色衝進白光。
- **判定**：以伺服器為準，加 0.15 秒寬限，或把判定範圍縮小一圈。不要用「閃光前的位置」判定，那對正在逃出黃區的人反而更不利。
- **手機觸控**：`touch-action: none`、`user-select: none`、`-webkit-touch-callout: none`；用 pointer events，並處理 `pointercancel`（例如通知跳出來時）。
- **螢幕**：加入後請求 Screen Wake Lock，避免等開局時螢幕自動鎖定。

## 10. 技術架構

- **伺服器**：一個常駐程式（不要用 serverless），所有展廳都是記憶體裡的分區。
- **遊戲邏輯**：寫成一個獨立的純邏輯模組（輸入目前狀態、玩家輸入、經過時間，輸出新狀態和事件），伺服器和之後的 bot 共用同一份；判定以伺服器為準。
- **更新節奏**：伺服器每秒更新 20 次；每廳每秒推 10 次位置快照給該廳的手機（座標用小整數）；投影接收全部展廳。投影和手機都做平滑補間。
- **地圖**：一條座標軸。畫框、安全區、照射區、出口都用固定座標，顯示和判定共用同一份設定。
- **訊息格式（草案）**：
  - 手機 → 伺服器：`join {section}`、`input {dir: -1 | 0 | 1}`（改變時才送）、`hold`（按住時每 200ms 送一次）。
  - 警衛 → 伺服器：`target {room, gap}`、`cancel {room}`、`switch {room}`。
  - 伺服器 → 手機：`snapshot {t, light, charges, players}`（每秒 10 次）、事件 `yellow / flash / caught / escaped / end`、個人狀態 `{rank, status}`。
- **網路**：200 條 WebSocket 會從同一個對外 IP 進來，先確認主機或 CDN 不會擋；WebSocket 被擋時要能退回 polling。

## 11. 用 bot 調難度（建議做法）

- 寫一個模擬器：三種玩家 bot（保守：只在安全時移動；貪心：一直往前，人在黃區裡才躲；新手：反應慢 0.4–0.7 秒，偶爾判斷錯）加上 bot 警衛，每組參數跑一千局。
- 目標：
  1. 前三名裡，保守 bot 占不到 15%。否則就是還太簡單。
  2. 貪心 bot 占前三名 45% 以上，而且平均被抓 1.5 次以上。否則就是警衛太弱。
  3. 新手 bot 有 50–70% 逃得出去。否則第一次玩的人會被輾壓。
  4. bot 警衛平均擋下每廳 30–50% 的人。
- 同一批 bot 改用真的 WebSocket 連線，就是 200 人的壓力測試。
- 沒時間做模擬的話，就用真人試玩對照這四個目標，數值以試玩結果為準。

## 12. Demo 流程

- **投影片 1**（pitch 時）：一句話加上大 QR code。大家邊聽邊掃碼、選座位區，看自己的肖像走出畫框。
- **投影片 2**：切到即時監控畫面。
- **0:00–0:45**：第一局，所有展廳同時開始；一位評審當真人警衛，從評審那一廳開始巡邏。
- **0:45–1:00**：名人堂，各廳前三名的肖像掛上牆。
- **1:00–1:45**（時間夠才做）：決賽，30 位前三名在同一廳，評審當警衛；或者直接再打一局。
- **pitch 可以用的句子**：
  - 「美術館版的一二三木頭人。」
  - 「兩百幅畫、十個展廳、一個警衛。」
  - 「我們讓 bot 打了一千局來調難度。」
- **退路**：多廳版本來不及，就用一個展廳加上 bot 補位來 demo。

## 14. 風險與對策

| 風險 | 對策 |
|---|---|
| 還是太簡單 | 依模擬結果調照射寬度、電量、定身時間 |
| 太難，新手被輾壓 | 守住「新手 bot 逃脫率 50–70%」的目標；加長寬限或縮小照射寬度 |
| 延遲造成冤枉 | 判定寬限、保活停步、判定範圍縮一圈 |
| 找不到自己的角色 | 手機走廊縮圖，自己放大並加框 |
| 場地 Wi-Fi 撐不住 | 小封包、200 bot 壓測、現場實測、退回 polling |
| 評審事後一個人試 | bot 補位 |
| 開局後才進來的人 | 從出生框直接加入 |
| iOS 長按跳出選取 | 觸控 CSS 加上 pointer events |
| 截止時間 | 今晚就問主辦 |
